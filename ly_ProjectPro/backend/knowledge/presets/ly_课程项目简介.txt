二、技术栈要求
1. 前端：原生 HTML、CSS、JavaScript 三件套，禁止引入任何第三方库、框架与 CDN 链接；CSS 类名、JS 变量名、函数名一律以 ly_ 开头。
2. 后端：Node.js + Express，RESTful + MVC 风格（routes/controllers/models 三层目录），所有接口以 /api/ 为前缀，端口固定 8220，使用 express.static 托管前端静态资源，cors 中间件开放跨域（仅课程作业使用）。
3. 数据库：MySQL，凭据写入 backend/.env，统一 JSON 响应格式 { code: 0, msg, data }。

三、过程记录要求
1. liuyue_prompt.md（项目根目录）：每次向 AI 发出开发指令后追加记录时间、提示词全文与大模型名称。
2. backend/ly_interface.md：每次创建或修改接口后追加接口路径、HTTP 方法、请求参数与响应格式示例。
3. backend/ly_database.md：每次建表、改表或插入数据后按执行顺序追加 SQL，要求仅凭此文件即可在新机器上完整重建数据库。

四、评分要点提示
1. 功能完整性：每个页面均能通过后端接口取到数据库真实数据，而非写死在前端的假数据。
2. 代码规范：命名前缀、文件头注释块（姓名、学号、时间、大模型）齐全。
3. 交互体验：成功与失败均有提示，错误信息输出到浏览器控制台。
4. 创新加分项：接入大模型 API 实现 AI 聊天、在线客服与 RAG 知识库问答属于创新功能。

五、AI 应用说明
项目接入两家大模型服务：硅基流动（SiliconFlow，用于 AI 聊天页）与七牛在线客服（qiniu/conatus-free，用于在线客服页），二者均为 OpenAI 兼容接口，API Key 统一存放在 backend/.env，不下发到浏览器。RAG 问答采用关键词检索方案：上传文档解析为文本后按段落分块存入 MySQL，提问时对分块进行关键词评分，取最相关的若干块拼入提示词交给大模型生成答案，并在页面展示引用来源。
